> 状态：设计与现有实现对照稿  
> 更新日期：2026-09-09  
> 范围：当前桌面、玩家卡片、卡牌区域、公共工具，以及 `SANGO_PUBLIC_TABLE_V3.html` 中的牌堆和统一弃牌区设计。

## 标记说明

### 实现状态

| 标记 | 含义 |
| --- | --- |
| 正式 | 已存在于正式组件或 `gameController` 中 |
| 部分 | 已有底层能力，但新版入口、业务语义或完整流程尚未实现 |
| Mock | 仅在 `SANGO_PUBLIC_TABLE_V3.html` 的内存设计稿中运行 |
| 规划 | 规则已经讨论，但设计稿和正式代码都未完整实现 |

### 日志状态

| 标记 | 含义 |
| --- | --- |
| ✅ 已有 | 正式本地行动日志能识别该状态变化或 action hint |
| ⚠️ 部分 | 有日志，但文案无法准确表达业务动作，或只有旧入口有日志 |
| ❌ 尚无 | 正式日志目前无法记录该行为 |
| — 不记录 | 纯本地查看、选择或未提交草稿；按当前规则不应进入行动日志 |

“已有日志”指正式游戏中的本地行动日志。设计稿反馈文字、状态提示和演示按钮不算日志。

## 9. 日志当前边界

当前日志由 `actionLogPanel.js` 在客户端内存中维护，通过 `localActionLog.mjs` 比较前后房间状态，并在必要时读取 `runtime/a` 的 compact action hint：

- 首次 snapshot 只建立 baseline，不回放旧操作。
- 刷新、退出或重新进入后，当前日志清空。
- 日志不是持久化历史，也不保证所有客户端严格一致。
- 当前日志面板最多保留 500 条本地记录。
- 纯查看、选择、滚动、打开面板、取消和未提交草稿不应写日志。
- 现有普通移动日志可以说明“牌从哪里移动到哪里”，但不能稳定区分打出、弃置、摸牌、收取等业务意图。
- 新版公共区正式实现前，需要为打出、弃置、摸牌、展示／判定和弃牌收取确定日志语义。

## 10. 正式实现前需要确认

清算和结算批次已经从设计中移除，建议不创建新的结算 container。正式实现前只需确认：

1. 弃牌堆的 `order` 是否是稳定、可跨客户端恢复的全序。
2. 打出、弃置和展示／判定是否都通过一次原子操作追加到弃牌堆末尾。
3. “最近 6 张”由客户端从有序弃牌中直接截取，不额外写入数据库。
4. 收取与洗牌后，最近弃牌能否从最新弃牌状态自动重算。
5. 私密观看牌堆时，服务端和日志都不能向无权限客户端发送牌面。
