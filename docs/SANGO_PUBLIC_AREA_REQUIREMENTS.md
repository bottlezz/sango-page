# 公共区域、牌堆与结算面板需求

状态：当前讨论基线，替代旧版“展示后再手动放入弃牌堆”的规则。设计预览仅使用本地数据，尚未接入正式多人对局。

## 区域与术语

| 名称 | 含义 | 可见性 |
| --- | --- | --- |
| 牌堆 | 有顺序的牌集合，从顶部摸牌；可展开调整顺序 | 默认牌背；观看权限需另行确定 |
| 弃牌堆 | 当前已弃置的实体牌，包括打出、弃置、牌堆展示／判定的牌 | 所有人可查看全部 |
| 结算面板 | 本批进入弃牌堆的牌的公开展示，引用弃牌堆中的牌，不额外持有一份牌 | 所有人可见 |
| 亮牌 | 公开玩家某区域里的牌，保留原区域和归属 | 所有人可见；独立显示方案待定 |

“结算牌已在弃牌堆”是本游戏当前采用的操作约定，不表示自动实现所有实体游戏的技能时序。

## 已确认操作

| 操作 | 牌的流向 | 产生结算行动 |
| --- | --- | --- |
| 摸牌 | 默认取牌堆顶部 1 张 → 操作玩家手牌 | 否 |
| 展开／调整牌堆、观看牌顶 | 可调整顺序、放到底部，或加入“确认后摸牌” | 否 |
| 玩家打出 | 原区域 → 弃牌堆，同时在结算面板显示 | 是 |
| 玩家弃置 | 原区域 → 弃牌堆，同时在结算面板显示 | 是 |
| 牌堆展示／判定 | 默认取牌堆顶部 1 张 → 弃牌堆，同时在结算面板显示 | 是，同一个操作的不同场景 |
| 玩家亮牌 | 原区域及归属不变，只改公开状态 | 否 |
| 收取结算牌 | 弃牌堆 → 收取玩家手牌 | 否 |
| 手动清算 | 清空本批面板展示；不移动、不删除弃牌 | 否 |

不再提供“放入弃牌堆”按钮。弃牌堆默认收起；数量已包含当前结算牌，不能把两边数量相加。

## 结算批次与刷新

记录“本批结算行动玩家”。打出、弃置、牌堆展示／判定才产生结算行动。

1. 尚无批次：创建新批次。
2. 同一玩家连续结算：追加到本批。这是根据现有刷新条件推导的设计默认值。
3. 不同玩家产生结算行动：面板换为新批次，旧批次的牌仍在弃牌堆。
4. 摸牌、整理、观看、亮牌、区域转移、收取结算牌不换批，也不改变“本批玩家”。
5. 手动清算清空展示并取消本批，下一次结算重新开批，即使仍是原玩家。
6. 仅切换回合或操作视角不刷新；失败、取消、未选牌的操作不刷新。

| 示例 | 面板结果 |
| --- | --- |
| A 打出两张 | A 批次，两张已在弃牌堆 |
| A 再弃置一张 | A 批次追加，共三张 |
| B 收取其中一张 | 仍为 A 批次；该牌移出弃牌堆，面板标记已收取 |
| B 摸牌／亮牌 | 仍为 A 批次 |
| B 打出一张 | 更换为 B 批次；旧牌仍可在弃牌堆查到 |
| 手动清算 | 面板为空，弃牌堆不变 |

预览保留“已收取”占位帮助理解结算过程，收取按钮消失；该显示方式尚可调整。全部被收取也不自动更换批次玩家。

## 牌堆展开与排序

- 摸牌和牌堆展示／判定不提供张数输入，每次固定操作牌顶 1 张；连续操作通过重复点击完成。
- “展开牌堆”进入排序界面，默认显示牌背和顺序编号。
- 提供前移、后移、放牌底／放牌顶，以及“确认后摸牌”。指定摸取的牌进入第三列，并在确认时加入操作玩家手牌。
- 确认是一个整体操作：从牌堆移出第三列的牌、写入玩家手牌并提交剩余牌序。关闭和 Esc 丢弃全部草稿，不摸牌，也不改变牌序。
- 取消可以撤销牌序与摸牌草稿，但不能撤回玩家已经看见的牌面；操作日志应保留观看行为所允许公开的最少信息。
- 不输入观看张数。展开界面中的每张牌都有“观看”按钮，玩家用鼠标逐张翻看；未点击的牌保持牌背。观看与公开并弃置的“展示／判定”不同。
- 最终顺序：牌顶列从上到下 → 牌底列从上到下；最后一张是最终牌底。“确认后摸牌”列按从上到下进入玩家手牌，不再留在牌堆中。
- 牌堆相关设计不要求键盘输入；摸牌、展示、观看、排序、放底和确认均可只用鼠标完成。
- 预览允许全堆排序以讨论交互。正式版本能排序的范围、能观看的范围应按技能或房间约定限制。

## 玩家亮牌的建议（尚未定案）

建议在原卡牌上标注公开，玩家卡旁提供“已亮牌”入口；展开后用只读牌面镜像呈现，明确玩家与来源区域。镜像不持有实体牌，也不能误触发弃置。

需要吸引全桌注意时，可短暂显示“玩家 A 亮出两张牌”通知，点击进入上述面板。独立展示可避免清算时误以为这些牌也被弃置。

待定：公开持续到何时、移动后是否仍公开、谁能暗置。此次原型使用原区域公开状态，不制作新的亮牌面板。

## 尚需推敲的情况

1. **行动玩家定义**：A 的技能让 B 弃牌，该次归 A 还是 B？普通操作暂按发起人分批；复杂技能需要同时记录发起人和牌主。
2. **响应链**：A 杀、B 闪、A 再响应会连续换批。当前遵循按玩家更换的规则，可后续增加事件历史入口。
3. **同一玩家的不同回合**：当前继续追加，直到其他玩家结算或手动清算；不因为仅换回合自动分组。
4. **清算与收牌权限**：谁能清算、何时能收牌、两个玩家同时收取如何处理，需要正式规则约束；界面按钮不等于技能权限。
5. **判定改判**：旧判定牌、替换牌何时弃置，归谁的批次，需技能流程决定。预览不判断判定结果。
6. **洗牌与耗尽**：弃牌洗回牌堆后结算引用必须失效或标记已离开。当前空牌堆阻止取牌，不自动洗牌。
7. **唯一归属与历史**：结算与弃牌浏览引用同一张牌，收取不能复制。跨洗牌历史应保存为事件记录。
8. **并发与私密观看**：正式版本需原子更新归属与批次、锁定排序快照，防止重复收取或旧顺序覆盖新操作；未授权客户端不能收到私密牌面。
9. **断线与撤销**：恢复同一个公共批次；取消未提交排序可恢复原状，已经公开的牌面无法从玩家记忆撤销。
